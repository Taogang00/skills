# Java 数据安全检查

静态代码审查，聚焦两件事：敏感数据脱敏、数据范围鉴权（水平越权/IDOR）；不含功能级（角色/权限注解）授权。从 Controller 路由入手，沿 DTO → Service → Mapper/SQL → 返回 DTO/导出追踪；覆盖所有读写入口（`@GetMapping`、`@PostMapping`、`@PutMapping`、`@PatchMapping`、`@DeleteMapping`、`@RequestMapping`，按实际 HTTP method 判断行为）。以仓库实际使用的框架、数据访问方式和脱敏库为准理解代码，先读实现再判断语义；无法静态确认的结论标注待核实。

## 一、敏感数据脱敏

### 什么时候脱敏

按字段真实含义判定，不按字段名。脱敏只发生在前后端交互。

**必须脱敏**

| 类别 | 字段 |
|------|------|
| 身份证件 | 居民身份证号、驾驶证号、护照号、港澳台通行证号、外国人永久居留证号 |
| 联系方式 | 手机号、固定电话、传真、电子邮箱 |
| 车辆信息 | VIN码 |
| 地址位置 | 住址、户籍地址、联系地址、精确到门牌的经营场所地址 |
| 金融信息 | 银行账号、银行卡号、支付账号 |

**无需脱敏**

| 类别 | 字段 |
|------|------|
| 主体名称 | 企业名称、机构名称、分支机构名称 |
| 主体与车辆标识 | 统一社会信用代码、组织机构代码、经营许可证号、业务证照编号、车牌号 |
| 人员姓名 | 法定代表人、负责人、经办人、联系人等各类姓名 |
| 业务编号 | 申请编号、案号、档案号、流水号 |
| 日志 | 日志输出暂时不考虑脱敏，脱敏只发生在前后端交互 |

无需脱敏的字段不套用脱敏策略，对这类字段做模糊化按缺陷处理。

### 怎么做

沿 DTO 和对象映射追踪敏感字段（请求 DTO → Service 模型 → 实体 → 响应 DTO、嵌套对象、导出模型），用仓库所用脱敏注解与策略覆盖实际序列化路径，例如：

```java
@Sensitive(strategy = SensitiveStrategy.ID_CARD)
private String idCertNum;

@Sensitive(strategy = SensitiveStrategy.MOBILE_PHONE)
private String mobile;
```

逐项检查：

- **策略匹配**：按字段含义选策略；无需脱敏字段不得套用。
- **模型覆盖**：列表、详情、分页、统计、导出等所有响应模型都覆盖，尤其手工组装的 DTO。
- **绕过路径**：手工拼装 JSON、模板渲染、直接返回实体、跳过脱敏的序列化器或注解；错误响应同样不得暴露原值。
- **真的生效**：不能假设"加了注解就一定生效"，沿序列化器配置与调用链确认；Excel、CSV、PDF 等非 JSON 输出同样处理。

## 二、数据范围鉴权

### 什么时候需要

越权判定依赖"数据属于谁"。先确认资源归属维度，未确认的维度按"未知"标注，不得默认放行；归属不明确时向用户确认，不自行假设：

| 归属维度 | 典型字段 | 说明 |
|---------|---------|------|
| 管辖机构 | `orgId`、`orgCode` | 层级机构（仅本级 / 本级 + 下级） |
| 管理部门 | `deptId`、`manageDeptId` | 独立于机构树，不套用层级继承 |
| 企业/业户 | `ownerId`、`socialCreditCode` | 企业账号的数据边界 |
| 从业人员/驾驶员 | `pracId`、`idCertNum` | 个人账号只能访问本人数据 |
| 区域 | `areaCode` | 行政区划 |
| 车辆/设备 | `vehicleNum`、`plateColor` | 按归属企业或归属人校验 |

以下场景必须做范围校验，无一例外：

1. **按归属字段过滤的列表、分页、统计、导出**：`orgId`、`orgCode` 等作为查询条件。
2. **按归属或资源标识查询**：凡客户端可控、决定"查谁的数据"的标识（路径变量、查询参数、请求体均可携带）。传 `ownerId` 先校验对应业户是否是当前账号可查看的业户；查车辆先校验该车辆是否在可查看范围内；按记录 ID 取数先校验记录归属。
3. **写操作**：创建、更新、删除、提交、指派、导入及批量，同样按归属校验。

免登录、公示等公开接口不默认豁免，须有明确业务目的和有限输出；无法确认批准依据的列为待核实。

### 怎么做

**1. 范围锚点必须来自服务端可信身份（强制）**

身份取自类似 `AccessContextHolder.getUserInfo()` 的可信上下文，不能由客户端伪造或前端传入。凡是涉及 SYS_ORGANIZE 机构维度的查询（查机构表本身，或以 `orgCode` 过滤业务数据），Controller 必须注入默认查询条件 `currentOrgCode`，唯一合法赋值来源是当前登录人机构编码：

```java
String orgCode = AccessContextHolder.getUserInfo().getOrgCode();
query.setCurrentOrgCode(orgCode);
```

- 取自请求参数、前端 DTO 字段、硬编码或其他来源的，一律判为缺陷。
- 必须追踪到对应的 Mapper XML 或查询方法，确认条件真正进入 SQL；只设字段、查询中不使用，视为未生效。

**2. 其他归属维度：未传兜底或拒绝 + 传入校验**

```java
@GetMapping("/list")
public R<List<Xxx>> getResultList(XxxQuery query) {
    if (EmptyUtil.isEmpty(query.getOrgId())) {
        // 未传机构条件：用当前登录人的机构兜底，避免条件缺失退化为全量查询
        query.setOrgId(AccessContextHolder.getUserInfo().getOrgId());
    } else if (!canAccessOrg(query.getOrgId())) {
        // 传了机构条件：必须落在当前登录人可访问的范围内（含允许的下级）
        throw new NoStackBizException("查询的数据信息不是当前登录用户下的，禁止操作！");
    }
    return R.OK(xxxService.getResultList(query));
}
```

判定标准：

| 实现写法 | 结论 |
|---------|------|
| 无条件覆盖前端传值，直接以登录归属为准 | 通过（优先推荐） |
| 未传则兜底 + 传入则校验且覆盖允许范围 | 通过 |
| 未传则显式拒绝 | 通过 |
| 无兜底、无校验 | 缺陷：未传全量，传入可越界 |
| 只兜底、不校验 | 缺陷：可传他人归属值查询 |
| 只校验、未传时既不兜底也不拒绝 | 缺陷：未传退化为全量 |
| 有校验但只比对本级、未覆盖允许的下级或条线 | 缺陷：范围不完整 |

**3. 目标校验（按归属/资源标识查询时必检）**

两种实现等价有效：

- **先校验再查询**：先按标识查出目标的归属字段，比对是否落在可访问范围内，不在则拒绝。
- **查询内约束**：把目标标识与可信范围条件一并写入 SQL，无权时返回空结果。

无论哪种，最终查询都要同时受目标标识与可信范围约束，不能校验完就直接按客户端值查。

**4. 层级规则**

层级范围只含本级及规则允许的下级，明确排除平级与上级；不能把"同属一棵组织树"视为都可访问：

```text
机构1（上级）        orgCode = JTT_
  └─ 机构2（当前登录）  orgCode = JTT_NJ_
       └─ 机构3（下级）  orgCode = JTT_NJ_JN_
机构4（与机构2平级）  orgCode = JTT_SZ_
```

机构2 只能访问机构2 与机构3（及其下级），不能访问机构1、机构4。仓库常用前缀式层级编码计算范围：按含尾部分隔符的 `JTT_NJ_` 前缀匹配不会误匹配 `JTT_NJX_`，但不带尾部分隔符的 `JTT_NJ` 会，以仓库实际编码规范核对。

**5. 写操作与批量**

- 创建、导入时，所有者、归属企业、机构等字段由服务端确定，或逐条校验请求数据。
- 更新、删除优先把资源 ID 与可信归属条件一起放进 `UPDATE`/`DELETE` 条件，并处理影响行数为 0 的情况。
- 作废、审核、提交、指派等状态变更同样校验归属，不能因为不返回数据就当作低风险。
- 批量操作对每条记录校验，或让批量 SQL 本身受可信范围约束；只校验第一条不足以证明安全。
- 对被复用的校验方法（`canAccessOrg`、基类、切面等）查看实现，记录它**实际**保障的条件而不是名字暗示的；空参数跳过检查、异常被吞、集合只校验部分元素，均视为缺陷。

## 三、结果报告

报告开头列出归属维度清单及来源（用户确认 / 代码推断），未确认的标注待核实。每个发现包含：位置与证据（文件/行号、Controller → Service → Mapper/SQL 调用链）、利用场景与影响、修复方向、状态与置信度。没有发现问题时，说明检查过的接口与数据路径、未覆盖范围，部分检查不得表述为完整审计。不记录真实身份证号、手机号、凭据、令牌和生产标识符。
