# 部门周报汇报整理规则

## 解析源文件

系统团队周报导出文件按成员分段，每段包含“本周工作内容”和“下周工作计划”。本周工作通常具有以下结构：

```markdown
- 【指挥调度】
1. 【新增】某项工作内容
2. 【修复】某项工作内容
```

将最近出现的系统标签视为后续编号工作项的业务方向，直到出现新的系统标签或进入下周计划。下周计划没有强制系统标签，需要根据原文谨慎分类。

忽略以下内容：

- `[TOC]`、周会说明、HTML 字体标签、成员标题和分隔线。
- `暂无工作内容`、`暂无下周计划`、空条目和纯模板提示。
- 与实际工作或计划无关的说明文字。

## 本周完成工作

业务方向固定按以下顺序输出：

1. 指挥调度
2. 综合执法
3. 综合治超
4. 一体化
5. 其他

分类规则：

- 显式系统标签匹配固定业务方向时，放入对应方向。
- 无法明确匹配、未知标签或纯公共事务放入“其他”。
- 一个条目包含多个系统标签时只保留一次；选择最明确的主业务方向，无法判断时放入“其他”。
- 不根据常识擅自改写业务方向。

类型固定按以下顺序排序：

1. 新增
2. 调整
3. 修复
4. 协调
5. 优化
6. 咨询

`会议` 或其他原始类型必须保留，排在上述固定类型之后；仅在源文件实际存在时显示和统计。工作条目统一输出为：

```markdown
1. 【新增】原始工作内容
```

只允许压缩多余空白和去除无意义 Markdown 包装，不改变原始语义，不添加完成度、效果或评价。

## 本周工作总结

- 统计所有业务方向中的有效工作条目。
- 每条只统计一次。
- 固定输出新增、调整、修复、协调、优化、咨询六类，即使数量为 `0`。
- `会议` 或其他类型存在时，在固定六类之后追加对应统计。
- 固定格式为 `- 【新增】3 项`。
- 所有类型数量之和必须等于“本周完成工作”的有效条目数。

## 下周工作计划

- 按指挥调度、综合执法、综合治超、一体化、其他的顺序排列。
- 计划原文明示系统或业务方向时使用对应方向；仅能根据内容明确判断时才推断，否则使用“其他”。
- 输出格式为 `1. 【指挥调度】原始计划内容`。
- 仅合并完全相同或语义上显然是同一事项的重复计划；相似但范围不同的计划分别保留。
- 多人都只写了泛化的“禅道任务和 Bug 处理”时合并为一条；包含具体任务、Bug 或业务内容时保留具体条目。
- 不从本周工作反推不存在的下周计划。

## 最终格式

严格按以下结构输出。没有工作内容的业务方向写 `- 暂无`，不省略固定标题。

```markdown
# 本周完成工作

## 一、指挥调度
1. 【新增】工作内容

## 二、综合执法
- 暂无

## 三、综合治超
- 暂无

## 四、一体化
- 暂无

## 五、其他
1. 【协调】工作内容

# 本周工作总结

- 【新增】1 项
- 【调整】0 项
- 【修复】0 项
- 【协调】1 项
- 【优化】0 项
- 【咨询】0 项

# 下周工作计划

1. 【指挥调度】计划内容
2. 【其他】禅道任务和 Bug 处理
```

不要在最终 Markdown 中附加成员名单、认证信息、处理说明或模型自评。
