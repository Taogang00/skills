# 部门周报汇报

将系统导出的成员周会 Markdown 聚合为部门级汇报稿。保持原始语义，不补写不存在的成果、数字、进度或计划。

## 选择数据来源

1. 用户已提供 Markdown 文件或原文时，直接读取并整理，不登录系统。
2. 用户明确要求从系统拉取时，先阅读 `references/api-contract.md`，再运行 `scripts/fetch_team_report.py`。
3. 用户只说“生成汇报”但未提供数据时，优先询问使用已有导出文件还是在线拉取。

## 在线导出

1. 确认 API 地址、登录账号和目标周次；目标周次使用 `YYYY-MM-DD` 表示该自然周内任意一天。
2. 告知用户：导出接口只读，但登录流程会按系统现有规则确保本周周报草稿存在，并可能自动导入上周计划。
3. 仅在用户已明确要求在线登录拉取，或确认上述副作用后执行脚本。
4. 不要求用户在对话中发送密码。优先让用户在本机设置 `WK_REPORT_PASSWORD`，或由脚本在交互终端使用隐藏输入。
5. 运行示例：

```powershell
$env:WK_REPORT_USERNAME = "your-username"
$env:WK_REPORT_PASSWORD = "your-password"
python scripts/fetch_team_report.py --api-base https://gw-ai-bot.online --week-date 2026-07-20 --ack-login-side-effects
```

6. 脚本完成后读取生成的 `*-weekly-meeting.md`。不要记录、回显或写入账号密码、`satoken`。

## 整理汇报

1. 阅读 `references/report-rules.md`。
2. 从每名成员的“本周工作内容”和“下周工作计划”提取有效条目。
3. 忽略模板标题、成员姓名、分隔线、`暂无工作内容`、`暂无下周计划` 等占位内容。
4. 按业务方向汇总本周工作，按类型排序并统计数量。
5. 按业务方向整理下周计划；只有原文能够明确判断时才分类，否则归入“其他”。
6. 对明显重复的同一条内容只保留一次；不要把相似但不同的任务强行合并。
7. 默认直接返回完整 Markdown 汇报稿；用户要求落盘时再写入指定文件。

## 质量检查

- 逐条核对输出内容都能在源文件中找到依据。
- 确认每条本周工作只统计一次，分类数量之和与有效工作条目数一致。
- 确认类型和业务方向排序符合规则。
- 确认未臆造下周计划，未泄露成员密码、令牌或其他认证信息。
- 只输出汇报稿和必要的简短说明，不附带内部推理过程。
